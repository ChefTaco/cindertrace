# Installation and configuration

`npm run init` creates unique secrets, an Argon2id administrator hash, a 90-day local
TLS certificate and HiveXUI's `ui/runtime.json`, without printing credentials. It
refuses to overwrite an existing environment. Configuration and state are local-only.

Compose runs the API, PostgreSQL, Redis, HiveXUI (`ui`) and the gateway. The collector
is an opt-in profile. The API exposes `/health`, `/ready` (database and Redis), the
suite-standard `/health/live` and `/health/ready` (per-dependency JSON, 503 when not
ready), and authenticated `/metrics`. Every response carries an `x-request-id`.

## The UI: HiveXUI in local mode

Cindertrace has no UI of its own. A standalone installation serves
[HiveXUI](https://github.com/ChefTaco/HiveXUI) in local mode, which shows only
Cindertrace's pages and signs in with the API's own local sign-in
([browser authentication](BROWSER_AUTH.md)):

- `ui` runs the HiveXUI image pinned by digest (override with `CINDERTRACE_UI_IMAGE`,
  HiveXUI 0.10.0 or later). It serves static files on port 8080 inside the Compose
  network only, as its own unprivileged account, read-only, with every capability
  dropped. `ui/runtime.json`, generated by init, is mounted read-only into its web root:
  `{"schema":1,"mode":"local","products":{"cindertrace":"/api/cindertrace"}}`.
- `gateway` runs `scripts/ui-gateway.mjs` from the Cindertrace image, read-only, as the
  installation account, with every capability dropped. It is the only published service
  (`127.0.0.1:${CINDERTRACE_UI_PORT}`, 3444 by default) and terminates TLS with
  `certs/server.crt` and `certs/server.key`. It forwards `/api/cindertrace/*` to the API's
  `/api/v1/*` over verified HTTPS, answers 404 for every other `/api/*` path, and serves
  everything else from `ui` (GET and HEAD only). It receives no product secret. Requests
  to the API carry only the `cindertrace_session` cookie and a short list of request
  headers (`Origin`, content and caching headers); `Authorization`, forwarding headers
  and other cookies are dropped, and static requests carry no cookie at all. Its health
  check fetches `/health` through itself and `ui`.

The page origin must equal the API's `DASHBOARD_PUBLIC_ORIGIN` (init sets
`https://localhost:3444`), because the API accepts browser sign-in and changes only from
that exact origin. Behind the gateway the API sees the gateway's internal address, not
the browser's, so sign-in throttling by source address treats all browsers as one source.

For a remote installation, replace the TLS certificate/key (keep `localhost` in its
names, or adjust the gateway and API health checks), set `DASHBOARD_PUBLIC_ORIGIN` to the
exact HTTPS origin people open, and publish the gateway on your chosen interface in a
`compose.override.yaml`. Set `NODE_EXTRA_CA_CERTS` to the issuing CA for private PKI.
Certificate verification must stay enabled. Renew certificates separately from code
releases.

The generated `CINDERTRACE_UID` and `CINDERTRACE_GID` match the installing user,
so the containers can write the private `state` bind mount and read `certs`. Set them
explicitly when installing for a dedicated service account and match directory
ownership. `ui/runtime.json` must stay readable by HiveXUI's account (mode 0644).
Back up state and PostgreSQL together.

Optional integration configuration is documented in INTEGRATIONS.md. Keep all
secrets out of browser variables, command arguments, logs, and Git.
`SECURITY_CONSOLE_TOKEN_SECRET` keeps its name: the API still accepts short-lived
tokens signed with it, which the bundled demo and integration scripts use.

Use the dedicated [upgrade command and recovery runbook](UPGRADING.md) for subsequent
releases. It supports Compose installations, with frozen backup/restore verification
before migration. Native systemd installations are no longer supported.
